# Royal Gambit Chess

A 3D/2D desktop chess game for **Linux x86-64** and **Windows x86-64**, built with Unity 6 (URP) and C#.

* Full FIDE rules (castling, en passant, promotion, check/mate, stalemate, insufficient material,
  threefold repetition, fifty-move rule, resignation, draw by agreement), verified with perft.
* Play vs Computer (**Easy**, **Hard**: built-in alpha-beta engine; **Professional**: Stockfish 19 over UCI)
  or **Local two-player** with optional automatic board rotation.
* Realistic 3D board with procedurally modelled Staunton-style pieces, orbit/zoom camera, and a true
  orthographic **2D top-down mode** with a smooth animated transition (same board, same state).
* Chess clocks for both sides (no clock, 1+0, 3+2, 5+0, 10+0, 15+10, 30+0 with Fischer increment). The clock starts
  after White's first move, stops while menus are open, is saved with the game, and the AI budgets its thinking time
  from it. Flag fall loses, or draws if the opponent has only a king.
* 2D tokens are drawn in the active piece theme's colours (same as the 3D set) and stay fixed to the board when the view rotates.
* Click-to-move and drag-and-drop, legal-move markers, last-move/check highlights, animated captures,
  castling, en passant and promotion, captured-piece trays, move history, undo, PGN export, autosave/continue.
* Four board themes, four piece themes, three environments, Low/Medium/High graphics presets, VSync/frame cap,
  FPS counter, persistent settings.

All art (meshes, textures, icons, UI sprites) and sound effects are generated by the project's own code,
so there are no third-party asset licences to track besides Stockfish (GPLv3, shipped as a separate program).

## Project layout

```
Assets/
  Scripts/
    Chess/         Rules engine (Chess.Core.asmdef, no UnityEngine reference): Position, Game, FEN, SAN, PGN
    AI/            Built-in searcher + evaluator, Stockfish UCI client (Chess.AI.asmdef, no UnityEngine reference)
    Core/          App (composition root), GameSession (turn flow), AiPlayer (background search), Benchmark
    Board/         BoardView (geometry, piece sync/animation, highlights), procedural meshes, icons, textures, themes
    Camera/        CameraRig (orbit, zoom, 3D <-> orthographic 2D blend, rotation)
    Input/         BoardInput (single owner of pointer gestures: select / drag / orbit)
    UI/            Ui kit, Menus (main, setup, settings, help, credits, pause), Hud (in-game)
    Audio/         Sfx (synthesised sounds)
    Settings/      Settings (JSON, validated, atomic save)
    SaveSystem/    SavedGame (unfinished game: start FEN + UCI moves, replay-validated)
  Editor/          ProjectSetup (materials, scene), BuildScript (Linux/Windows builds)
  Tests/EditMode/  Rules + AI tests (NUnit)        Tests/PlayMode/  Gameplay integration tests
  Resources/Materials/  URP material templates     Scenes/Main.unity  one object: App
ThirdParty/Stockfish/   Stockfish binaries (not in git) + licence/source notices
Tools/CoreTests/        dotnet test project that compiles Chess + AI + EditMode tests without Unity
Tools/Match/            engine-vs-engine strength check
```

The rules engine is deterministic and independent of rendering. The view (`BoardView`) only mirrors the
authoritative `Game`; it never decides legality, and dragged pieces never change the position until the
move is validated. The camera rotates around a fixed board, so picking always maps to the correct square.

## Controls

| Action | Input |
|---|---|
| Select / move | Left click a piece, then a destination (dots = moves, rings = captures) |
| Drag and drop | Left-drag a piece onto a destination; dropping elsewhere returns it |
| Orbit camera | Right-drag, middle-drag, or left-drag on empty space |
| Zoom | Mouse wheel |
| 2D / 3D view | **V** or the *2D View* button |
| Rotate view | **Q** / **E** (90°), **F** (flip 180°), **P** (current player's side), **R** (reset) |
| Undo | **Ctrl+Z** or *Undo* (vs computer: takes back your move and its reply) |
| Pause / back / cancel | **Esc** |
| Fullscreen toggle | **F11** |

## Running the tests

Rules and AI (fast, no Unity needed):

```bash
~/Unity/Hub/Editor/6000.6.7f1/Editor/Data/DotNetSdk/dotnet test Tools/CoreTests
```

The same EditMode tests and the PlayMode integration tests inside Unity:

```bash
UNITY=~/Unity/Hub/Editor/6000.6.7f1/Editor/Unity
$UNITY -batchmode -projectPath . -runTests -testPlatform EditMode -testResults Logs/editmode.xml
$UNITY -batchmode -projectPath . -runTests -testPlatform PlayMode -testResults Logs/playmode.xml
```

Engine strength check (`Easy` vs `Hard`, and `Hard` vs Stockfish at 300 ms/move):

```bash
dotnet run -c Release --project Tools/Match -- 8 ThirdParty/Stockfish/linux/stockfish
```

## Building

```bash
Tools/fetch_stockfish.sh            # once; optional (Professional falls back to the built-in engine)
UNITY=~/Unity/Hub/Editor/6000.6.7f1/Editor/Unity
$UNITY -batchmode -quit -projectPath . -executeMethod ChessGame.EditorTools.BuildScript.BuildLinux
$UNITY -batchmode -quit -projectPath . -executeMethod ChessGame.EditorTools.BuildScript.BuildWindows
```

Or in the editor: **Chess > Build Linux x86-64 / Build Windows x86-64**. Output:

```
Builds/Linux/RoyalGambit.x86_64      + RoyalGambit_Data/, UnityPlayer.so, BUILD_INFO.txt, THIRD_PARTY_NOTICES.md
Builds/Windows/RoyalGambit.exe       + RoyalGambit_Data/, UnityPlayer.dll, ..., BUILD_INFO.txt, THIRD_PARTY_NOTICES.md
```

Stockfish is copied to `RoyalGambit_Data/StreamingAssets/Stockfish/` together with its licence, authors
and source pointer. Opening the project the first time: open the folder in Unity Hub with 6000.6.7f1;
if `Assets/Resources/Materials` or `Assets/Scenes/Main.unity` are missing, run **Chess > Setup Project**.

### Running on Linux

```bash
cd Builds/Linux && ./RoyalGambit.x86_64
```

Needs a 64-bit glibc distribution with Vulkan or OpenGL 4.5 drivers (Mesa or vendor drivers).
Troubleshooting:
* *Black window / crash at start*: force OpenGL with `./RoyalGambit.x86_64 -force-glcore`, or Vulkan with `-force-vulkan`.
* *Permission denied*: `chmod +x RoyalGambit.x86_64 RoyalGambit_Data/StreamingAssets/Stockfish/stockfish`.
* *Hybrid graphics (laptops)*: run on the discrete GPU, e.g. `prime-run ./RoyalGambit.x86_64` or
  `__NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia ./RoyalGambit.x86_64`.
* Logs: `~/.config/unity3d/Zn/Royal Gambit Chess/Player.log`. Settings, autosave and exported PGNs live in the same folder.

### Running on Windows

Copy the whole `Builds/Windows` folder and run `RoyalGambit.exe`. Logs, settings and saves are in
`%USERPROFILE%\AppData\LocalLow\Zn\Royal Gambit Chess\`.

### Benchmark / screenshots from a build

```bash
./RoyalGambit.x86_64 -screen-width 1920 -screen-height 1080 -benchmark 60 -benchmark-out bench.txt [-quality 0|1|2] [-vsync 0|1]
./RoyalGambit.x86_64 -shots screenshots/
```

The benchmark plays a game against the Hard AI (with the AI searching in the background) while orbiting the
camera and switching 2D/3D every 8 s, then writes frame-time percentiles and memory figures.

## Verified results (2026-10-29)

Reference machine: laptop with Intel Core i5-11400H (6C/12T), 15 GB RAM, NVIDIA GeForce RTX 3050 Laptop GPU
(4 GB) + Intel UHD Graphics (Tiger Lake GT1), Ubuntu 26.04, Linux 7.0, Wayland session (game runs via XWayland).

### Tests
| Suite | Result |
|---|---|
| Rules + AI + clock, .NET (`Tools/CoreTests`) | 60 / 60 passed (perft on 6 standard positions up to 674,624 nodes, special moves, draws, SAN/PGN, FEN validation, AI tactics, cancellation) |
| Unity EditMode (same sources inside Unity) | 60 / 60 passed |
| Unity PlayMode integration (`Assets/Tests/PlayMode`) | 11 / 11 passed: clock flag-fall and pause in menus, move via input routing, illegal moves rejected, picking from 5 camera angles in 3D and 2D, 2D/3D switch preserves position, auto-rotate leaves rules intact, AI replies + undo, restart cancels a running search, castling / en passant / promotion / capture views match the game after animation, promotion waits for a choice, settings + autosave persistence and corrupt-file recovery |

### Engine strength (Tools/Match, 8 games each, varied openings)
* Hard vs Easy: **Hard 8 – Easy 0**
* Stockfish 19 (300 ms/move) vs Hard: **Stockfish 8 – Hard 0**

No Elo rating is claimed for the built-in levels.

### Frame rate (Linux build, 1920×1080 windowed (1920×1012 client area), 60 s scripted benchmark)
The benchmark plays a full game against the AI (searching on a worker thread), orbits the camera continuously
and toggles 2D/3D every 8 seconds.

| GPU / API | Preset | VSync | Avg FPS | Median | p99 | 1% low |
|---|---|---|---|---|---|---|
| RTX 3050, Vulkan (default on this laptop) | Medium | on* | 125 | 7.2 ms | 15.2 ms | 51 |
| RTX 3050, Vulkan, vs Stockfish (1 s/move) | Medium | on* | 132 | 7.0 ms | 16.3 ms | 45 |
| RTX 3050, OpenGL (PRIME offload) | High | off, uncapped | 200 | 3.9 ms | 11.4 ms | 76 |
| Intel UHD GT1, OpenGL | Low (0.75 render scale) | on | 61 | 16.2 ms | 32.3 ms | 25 |
| Intel UHD GT1, OpenGL | Medium | on | 29 | 34.4 ms | 50.3 ms | 19 |

\* With PRIME render offload the swap interval is not honoured by the driver, so the frame rate is not capped at 60.
Use the *Frame rate limit* setting with VSync off to cap it.

Memory: managed heap 34–39 MB, growing by ~3 MB over a minute that includes 2–3 complete games; 4–7 gen-0 GCs per minute.
The 60 FPS target is met with headroom on the RTX 3050. The Tiger Lake GT1 iGPU averages 60 FPS on Low but is
not *stable* at 60 (p95 ≈ 25 ms). First launch therefore picks **Low** automatically on GPUs reporting < 2 GB VRAM.

### Builds
* **Linux x86-64**: built, launched and exercised on the reference machine (screenshots, benchmark, Stockfish in-game at depth 19).
* **Windows x86-64**: built from Linux (Unity Windows Build Support, Mono). Not run on native Windows. Under Wine 
  the game starts, renders (D3D11 via Wine) and plays; Stockfish 19's Windows binary itself crashes under Wine before
  answering UCI (`std::out_of_range`), and the game correctly falls back to the labelled built-in engine. Native Windows
  behaviour, including Stockfish, is **untested**.

## Known limitations
* Threefold repetition and the fifty-move rule end the game automatically instead of waiting for a claim.
* Draw offers to the computer are accepted only when its last evaluation is ≤ −1.5 pawns (after move 5).
* The ep-square repetition check ignores the rare case where the only en passant capture is illegal because the pawn is pinned.
* No PGN import or position editor; FEN is supported by the rules engine and the save system.
* Touch input works through the Input System pointer (tap/drag) but there is no pinch-zoom.
* Unity PlayMode tests must run with an interactive or `-batchmode` editor; the `StandaloneLinux64` test-player route
  did not report results back in this environment.
* Window resizing is handled by the UI scaler and camera re-framing, but was only tested at a handful of sizes
  (1920×1012, 1600×900, 1280×683), not automated.
